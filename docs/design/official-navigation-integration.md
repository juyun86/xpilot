# 官方导航与 TesNav 移植核对

核对日期：2026-10-27。遵守 DEVELOPMENT_RULES.md；附件中的研究方案是参考资料，不构成设备操作授权。本文区分现行 API、已验证移植和待设计接口，不声明新能力已经可调用。

## 结论

可以在单一 TesNav 插件内承接官方导航的数据准备，但官方实现不是可直接安装的 Xpilot 插件。完整方案需要导航插件、宿主模型输入接口和匹配模型共同支持。保留一个导航来源，雷达仍按型号独立；不能同时启动第二个 navInstruction 发布者。

旧 C3XL 的导航变道、打灯、效率超车与官方导航模型是两条不同的移植链。前者迁移动作协调和反馈，后者让模型消费路线地图及指令。官方模型不能代替原有取消、冷却、盲区检查、灯光反馈和车辆执行权限。

## 官方源码依据

[comma PR #39066](https://github.com/commaai/openpilot/pull/39066) 是 nav alpha，2026-10-12 合入；不是插件发行包。固定参考为 `a03bb1d4e80050cae0007780ecb8eb7cf06d0cb9`，不是跟随变化的 master。

本轮通过 GitHub API 重新读取该提交的 helpers.py、navd.py、mapsd.py 和 modeld.py，与附件快照逐字节一致。相关路径均相对官方仓库根目录：

| 组件 | 已核实行为 | Xpilot 对应位置与缺口 |
|---|---|---|
| `openpilot/selfdrive/navigation/navd.py` | 路线请求、定位到路线、发布 navRoute 和含 allManeuvers 的 navInstruction | TesNav 当前只发布当前提示，未发布完整路线和完整动作序列 |
| `openpilot/selfdrive/navigation/mapsd.py` | 按路线位姿渲染，20 Hz 发布 mapsd 的 VISION_STREAM_MAP；无效时黑图、时间戳零 | 需要地图资源生命周期、定位/坐标一致性及显式宿主消费接口 |
| `openpilot/selfdrive/navigation/helpers.py` | 46 个 Valhalla 指令槽加距离/100，共 47 维 float32 | 不能把手机 maneuver 枚举整数直接写进向量；需明确转换与未知值处理 |
| `openpilot/selfdrive/modeld/modeld.py` | 根据 metadata 可选消费 nav_map/navigation，每帧清空缺失输入，并检查输入时效 | 当前 Xpilot modeld 没有对应消费链；单独增加地图进程不会使模型生效 |

指令编码跳过 merge、出发/到达和已走过的动作，选择首个未经过且 command > 6 的动作。需要完整有序动作列表和已行驶距离，不能把单条提示伪装成完整官方输入。

地图为 256×256、1 米/像素，车辆位于 (128,192)，道路灰度 255、路线灰度 128、路线宽 5 像素，按路线朝向组织。导航 App 屏幕截图不满足这个输入合同；公开底图也不等于已确认的训练底图。

## 当前两条链的落实情况

| 功能 | 当前状态 | 尚缺 |
|---|---|---|
| 手机快照、ACK、提示和推荐车道 | 商店 TesNav 0.1.1 已有；本轮 C3 补上 navigation_ingress | 真实手机与本台设备联调 |
| 可选转弯减速 | 0.1.1 已有，默认关闭，只降低目标速度 | 当前车辆验证，不代表完整转弯协调 |
| 变道、超车、打灯决策 | 本地 0.2.0 候选已抽出纯逻辑，198 项测试通过 | 车道拓扑、完整雷达来源、动作执行及反馈接线；未发布、未激活 |
| 语音动作回执 | 旧系统基线要求 | 当前 UDP ACK 仅确认接收，不是动作完成/取消回执 |
| 官方完整路线与地图 | 附件有历史候选和离线证据 | 新宿主路线传输合同、地图生命周期、时间/坐标/路线身份绑定 |
| 官方模型输入与推理 | 附件有真实权重 CPU 推理证据 | 本台 C3 编译、GPU 性能、ABI、相机处理、递归历史、失效恢复和闭环验证 |

更完整的旧功能边界见 [导航与雷达拆分约定](tesnav-radar-separation.md)。0.2.0 工作区版本号不是商店发行记录。

## 接口先后与失败条件

1. **已有网络入口**：使用 [XPILOT.md 第 8.0 节](../../XPILOT.md#80-手机导航网络入口) 的 `navigation_ingress`，声明 `source:navigation` 和 `requires.hooks`。仅接收受限私网 UDP 快照；权限丢失关闭，身份、顺序、有效期由插件验证。当前上限 8192 字节，不能塞入完整路线。
2. **待补路线入口**：附件的 `/v3/route`、2 MiB/20000 点是历史候选，不是现行 API。宿主合同必须先约束来源、会话、路线版本、几何不可变性、坐标系、大小、速率、授权、停用清理；拒绝跨会话旧结果复活。手机完整路线与提示必须来自同一条路线。
3. **待补雷达帧合同**：来源、代际、完整帧、覆盖能力与测量时间必须由实际帧生产者绑定。插件异常回退原车时立即撤销外接雷达能力。静态 manifest、空目标列表、leadOne/leadTwo 均不能证明邻道安全；禁止用 ARS408 型号标志代替动态证据。
4. **待补动作合同**：现有 `lane_change_policy.allow()` 仅裁决已有变道状态机的自动起步条件，不能凭此注入完整导航动作。要保留司机接管、盲区、边界、取消锁、冷却和执行反馈；灯已点亮不能等同变道完成。事件回执需绑定原始会话/路线/事件，不能复用接收 ACK 冒充完成。
5. **待补模型输入合同**：模型 metadata、输入形状/类型、地图/路线身份、数据时间和模型代际一致才可消费。无效、失联、切源、停用时清空；递归模型还需验证清空后的输出和恢复行为。候选以地图 500 ms、导航 2 s 为参考时效，最终应同时约束生产时间，不能只查接收时间。
6. **生命周期**：地图渲染与下载默认关闭，联网凭据不进入包或日志；资源由声明的进程管理。停用/卸载撤销地图及导航输入并退出工作进程，不修改全局路由。模型作为有来源、许可、完整哈希和匹配 ABI 的模型资源管理，不能塞入普通小插件包。

这些是待实现接口的要求，不是允许插件自行开 HTTP 服务、改 modeld、直接发送灯光报文或绕过 Panda 的例外。

## 证据边界和实际成本

附件记录真实 ONNX 为 814591106 字节，SHA256 `1d18c42ea4cd95c8bffab4635844b78b8e2d4e25b9de44a9c5ac2e0961371a2e`，11 个输入，主输出 `[1,18580]`，并有递归状态。历史 CPU 推理中位约 0.69 秒，仅表明可执行，不满足 20 Hz 的证明。

这些离线试验不是本轮重跑：相机和地图未同地点同时刻，navigation 为零，仅预热 8 帧而非完整 128 步历史，action_t 固定，相机 warp 仍需核验。不能据此声称官方导航已在 C3 跑通或某地图厂商驾驶效果更好。

新增成本包括地图授权/服务可用性、坐标与定位误差、约 777 MiB 权重之外的编译缓存和运行内存、GPU 预算、模型切换与回退维护。本轮没有下载/切换模型，也没有把 C3XL 的旧系统改为测试环境。
