# 特会开导航与多型号雷达的迁移约定

状态：用户已确认拆分方向；本文件是迁移目标和接口边界，不表示完整迁移已经实现。
遵守根目录 DEVELOPMENT_RULES.md。特会开导航仍为一个功能插件；各型号雷达独立接入。

## 已确认的功能基线

用户确认现有 C3XL 系统中的导航变道、打灯、超车等功能已经试用且可用。
迁移基线为设备活动提交 `6db98169cfefd6e7e4bd1f3bdaaf70623f79750d`；
用户的使用确认、源码核对和新插件移植后的回归验证分别记录，不能相互代替。

当前商店 tesnav 0.1.1 仅包含导航快照接收、提示、推荐车道显示和可选减速，
尚不等价于上述基线。后续迁移须保留导航靠边变道、效率超车、灯光协调、
语音回执、车辆反馈、取消/冷却与用户设置，不以这个子集重新定义用户需求。

## 功能归属

| 层 | 负责 | 不负责 |
|---|---|---|
| 特会开 App | 导航来源、路线/事件身份、导航状态、语音及回执 | 直接车辆执行权限、雷达硬件驱动 |
| 单一特会开导航插件 | 导航接入与显示、减速、选道/变道/超车决策、动作协调及设置 | 雷达型号协议、雷达硬件配置、绕过宿主或 Panda 的执行 |
| 各型号雷达插件 | CAN/硬件协议、安装与坐标转换、目标测量状态、完整帧/故障判断、所需配置报文 | 导航路线、超车策略或将未知邻道表示为安全 |
| 宿主 | 来源裁决、消息合同、通用融合接口、错误隔离与执行边界 | 某一雷达型号的业务解析和导航策略 |

ARS408 为已发现的现有实现来源。其他型号按实际硬件与协议确认后分别实现，
不得凭型号相近宣称兼容。雷达可供导航、跟车和显示共用，不从属于导航插件。

## 已有接口与待补合同

已有：`source:radar`、`Plugin.radar_interface(CP, CP_SP, params)`，返回
`update(can_list) -> RadarData | None`。card 统一发布 radarTracks，radard 消费原始
目标并发布 radarState。leadOne/leadTwo 不等价于完整邻道目标，不能替代超车所需输入。
原车接口并行运行；插件抛异常后当前实现会回退原车接口。

当前 `source:radar` 独占，支持在不同型号提供者之间裁决，不能让多个插件争抢
radarTracks 发布者。如需多传感器同时工作，须另行落实聚合提供者及融合合同，
不能将“多个可选型号”当作“已支持多雷达同时融合”。

待补：原始雷达来源/代际与能力的可验证绑定、覆盖范围、完整目标帧状态、
测量/预测语义、时间同步、安装偏置及故障回退后的能力失效。不能只读取静态
插件清单就认为当前 radarTracks 一定来自该插件；特别是原车回退时，必须让
依赖外接雷达能力的导航功能保守失效。新 API 应先完成宿主合同、能力探测和
检查，再让导航调用；本文件没有声明这些待补项已成为可调用 API。

导航消费统一的距离/横向位置/相对速度、目标身份、测量质量、时间和来源有效性，
不按型号二次解释字节或重复施加安装偏置。坐标及原点必须与当前融合栈一致，
每个雷达驱动以实际安装/协议证据完成转换，不按型号名推断。

## 现有耦合与降级边界

本次只读核对发现：旧 `nav_lane_intentd.efficiency_radar_healthy()` 既检查 radarTracks
与 modelV2 的有效性、时间和错误，还要求 `TeslaFlagsSP.ARS408_RADAR`。完整迁移时
将这一型号条件替换为上述真实来源和能力检查，同时保留时效、错误与同步条件；
不能仅删除标志条件而放宽到任意数据源。

旧 `efficiency_lane.lane_leads()` 使用完整原始目标、测量标志和模型车道几何，
并将雷达与模型坐标关联。这部分应保留其判断意义，硬件转换移到雷达提供者。

新鲜完整空帧、故障后空帧、目标丢失和覆盖未知必须区分。尤其不能因普通前向雷达
未提供邻道目标，就宣称邻道没有车辆。盲区、标线/路缘、司机接管、车辆权限和
现有控制/Panda 条件继续独立生效，雷达或导航来源都不能单独授予变道权限。

缺少所需雷达能力时，抑制对应的效率超车/目标判断，显示原因；导航接收与提示
继续工作。不得把这条规则解释为任意允许无雷达自动变道；其他动作仍需逐项满足
其本来所需的数据和权限。降级不清除原动作取消锁或制造新的路线/事件身份。

雷达配置发送按各插件实际需要声明 can.tx 与 Panda 运行时规则；既有接口或
用户确认功能可用，不自动证明新增固件/报文已验证或允许直接部署。

## 迁移验收

按一个导航插件保留既有设置和动作闭环。分别核对来源切换、插件故障回退、
缺包/停用、空帧、陈旧/乱序帧、坐标/速度方向、邻道覆盖不足、语音回执、
司机取消及失败恢复。回放和受控设备验证通过后再记录车辆验收。
本轮仅建立拆分约定与核对耦合，没有修改设备代码、参数、进程或固件。
